# 10.13 修改文档：PX4 式工作队列调度

修改日期：2026-10-13。

目标：将核心控制模块由“每个模块一个任务，循环计算后休眠”改为“共享工作队列、消息触发、定时兜底”。串口、CAN 和 Flash 保存继续使用独立任务。

本次采用 PX4 的调度结构思想，在项目现有 NuttX 和轻量 uORB 上实现所需组件，没有引入整个 PX4 平台或替换 NuttX 调度器。

## 1. 修改前后

修改前：

```text
RcUpdate任务：while → 处理一次 → sleep(10ms)
Command任务：while → 处理一次 → sleep(20ms)
Failsafe任务：while → 处理一次 → sleep(20ms)
RobotControl任务：while → 处理一次 → sleep(20ms)
ControlAllocator任务：while → 处理一次 → sleep(20ms)
```

修改后：

```text
NuttX独立任务 wq_safety（优先级110，栈8192字节）
    执行 RcUpdate::Run() 和 Command::Run()

NuttX独立任务 wq_control（优先级105，栈8192字节）
    执行 Failsafe::Run()、RobotControl::Run()、ControlAllocator::Run()

消息更新或兜底到期 → 调度工作项 → Run()完成一次计算并返回
没有到期工作 → 队列任务阻塞等待条件变量
```

保留的独立任务：

- `SbusInput`：USART3 非阻塞接收、SBUS 解码和输入失联检查。
- `CanOutput`：CAN 发送、接收、协议管理帧和 `MixingOutput`。
- `RobotRuntime`：初始化检查、诊断输出、参数 Flash 自动保存轮询。

注意：此前讨论中把 `RcUpdate` 原优先级写成100；实际源码为110。本次采用110，保持原调度优先级。

## 3. 既有文件的修改内容

### 3.1 公共生命周期

`robot/common/ModuleBase.hpp`：

- 增加 `WorkQueueTaskId=-2`，与独立任务PID区分。
- 增加工作项停止接口；`stop` 根据执行方式选择退出路径。
- 工作项停止时释放生命周期锁，等待正在执行的 `Run()` 返回，再取得锁释放对象。
- 工作项停止超时保留已禁用对象，提示再次 `stop`；不调用 `task_delete()` 删除共享队列任务。
- 独立任务原有启动、停止和状态命令继续使用原路径。
- 保留用户此前在该文件中的注释与缩进修改。

`WorkQueueModuleBase<T>` 中，`task_spawn()` 现在在命令上下文创建对象、附加队列、注册回调，激活调度。`instantiate()` 仍然存在并负责创建模块对象。它不再由独立模块任务的 `run_trampoline()` 调用。

### 3.2 消息总线

`robot/orb/uORB.hpp`：

- 增加 `Callback` 接口和每个topic最多8个回调槽位。
- 保留“最新消息 + generation”存储方式，不增加完整消息队列。
- `publish()` 先保存消息并释放数据锁，然后取得单独的回调锁，通知订阅者。
- 通知只请求 `ScheduleNow()`，不会在发布者任务中直接运行订阅模块。
- 注销回调使用同一回调锁，确保正在进行的通知结束后才返回。
- 普通 `Subscription` 和 `Publication` 的使用方式保持兼容。

回调不是中断接口。当前总线仍只允许任务上下文调用；回调内不能读取同一topic或执行耗时计算。

### 3.3 五个业务模块

修改这些类各自的 `.hpp` 和 `.cpp`：

| 模块 | 队列 | 回调订阅 | 周期兜底 / 最小执行间隔 |
|---|---|---|---|
| `RcUpdate` | safety / 110 | InputRc、ParameterUpdate | 10ms / 10ms |
| `Command` | safety / 110 | ManualControl、ManualControlSwitches、ParameterUpdate | 20ms / 20ms |
| `Failsafe` | control / 105 | ManualControl、ParameterUpdate | 20ms / 20ms |
| `RobotControl` | control / 105 | ManualControl、FailsafeStatus、ParameterUpdate | 20ms / 20ms |
| `ControlAllocator` | control / 105 | RobotControlSetpoint、ParameterUpdate | 20ms / 20ms |

公共改动：

- 继承 `WorkQueueModuleBase<T>`，删除各自独立任务的 `task_spawn()` 实现。
- 将相关订阅器替换为回调订阅器。
- 删除计算入口中的 `while` 和周期 `sleep()`，改为单次 `Run()`。
- 新增 `initWorkQueue()`、`unregisterCallbacks()`、`onWorkQueueStopped()`。
- 正常计算、RC安全互锁、失联策略、构型模型和矩阵分配算法继续复用。

补充改动：

- `RcUpdate` 新增状态锁，保护参数配置检查与状态查询。停止后立即发布无效输入状态。
- 四个已有状态锁的模块在锁内复制状态，锁外打印，减少串口打印占用状态锁的时间。
- `Command` 将上电开关警告写入原子通知字段，由 `RobotRuntime` 输出，避免共享队列中直接打印。
- `ControlAllocator` 的运行中构型变化仍令输出无效；重启提示改由 `status` 输出，队列中不打印。
- `ControlAllocator` 的 `instantiate()` 和构型工厂保留，默认双磁轮矩阵不变。

### 3.4 系统启动和构建

`robot/modules/RobotRuntime.cpp`：

- 参数初始化后启动两条工作队列；失败则拒绝创建runtime对象。
- `robot status` 增加队列名称、配置优先级、工作项数量、执行次数和单次最长运行时间。
- 独立100ms循环中增加 `Command::reportWarnings()`；Flash自动保存仍在这个任务执行。

NuttX端队列使用 `os::Task::spawn()` 创建独立任务组。没有把队列实现为归属于 `robot_core` 的pthread，避免与runtime任务组生命周期耦合。主机测试使用pthread后端，便于运行并发验证。

`config/nuttx/Makefile`：

- 加入 `WorkQueue.cpp`、`WorkQueueManager.cpp` 和对应VPATH。
- 增加 `CBOARD_NUTTX` 编译定义，选择NuttX任务后端；主机测试不用这个定义。
- NSH命令注册名称及业务入口保留。

`startup/etc/init.d/rcS`：更新启动提示，说明 `robot start` 同时初始化工作队列，模块启动顺序保留。

`README.md`、`robot/modules/README.md`、`startup/README.md`：更新调度结构和新增测试入口。

`tests/step3_runtime.ps1`：删除历史上“业务代码不能出现WorkQueue”的限制，改为检查没有引入PX4平台头文件。

`tests/step6_can_motor.ps1`：为已经迁移的模块增加工作队列链接依赖；已有协议、分配、失联和输出测试继续运行。

## 4. 调度行为和停止保证

1. 工作项初始化时只附加到队列，尚未激活；注册全部回调成功后才开启周期和首次执行。
2. 每个工作项最多保留一次待执行请求。多次topic通知合并，执行时读取最新数据。
3. 事件触发可以提前到来，但受最小执行间隔约束，避免消息高频发布产生忙循环。
4. 每次执行更新下一次兜底期限。没有新消息时，兜底仍检查超时并产生安全心跳；它不是独立的额外消息来源。
5. 队列在没有到期工作时等待条件变量；新工作或更早截止期限会唤醒队列。
6. 同队列选取最早到期的工作，截止期限相同时按附加顺序处理。不同队列和独立任务由NuttX根据任务优先级调度。
7. 停止顺序为：注销回调 → 禁止再入队 → 清除待执行和周期请求 → 等待正在执行的Run结束 → 发布安全消息 → 删除对象。
8. 停止超时不释放仍在执行的对象，也不杀死共享队列；保留对象允许再次停止。

周期单位为微秒。10/20ms是兜底及限频配置，不能解读为严格实时截止期保证。实际延迟包含锁等待、任务调度和计算时间。

停止后发布的消息：

| 模块 | 停止结果 |
|---|---|
| RcUpdate | 无效manual/switches，RC丢失状态 |
| Command | 未解锁的ActuatorArmed |
| Failsafe | active=true |
| RobotControl | 无效、failsafe=true的控制目标 |
| ControlAllocator | 无效motor/servo输出 |

## 5. 本次未修改的边界

- 不修改 `CanOutput` 的收发循环、非阻塞设备模式或管理帧2ms间隔。该文件已有用户注释改动保留。
- 不修改 `SbusInput` 的接收循环、协议解码器、CAN协议编解码器。
- 不修改参数Flash保存格式、扇区分配、控制分配公式和失联策略参数。
- 不修改NuttX上游调度器或启用时间片轮转。队列优先级是NuttX任务优先级。
- 停止单个模块不会关闭共享队列；`robot stop`仍只停止runtime，不代替各模块的stop。

## 6. 验证方法与结果

新增 `step7_work_queue.ps1` 验证：

- 初始化完成前不会执行模块。
- 等待较晚期限时能被较早请求唤醒。
- 重复通知合并和最小间隔生效。
- 无新消息时周期兜底仍执行。
- 取消、执行中停止超时与重试安全。
- 并发发布和注销不保留失效回调。
- 五模块通过真实InputRc消息完成处理、解锁和执行器目标发布。
- 停止输入后触发失联安全目标。
- 模块停止发布安全消息，重复启动不会泄漏回调槽位或工作项。

主机测试不会设置或验证NuttX实时优先级，也不能替代实板串口、CAN和电机测试。实板应额外检查 `ps` 中任务优先级、`robot status` 队列统计、遥控失联、单模块停止和电机安全行为。
